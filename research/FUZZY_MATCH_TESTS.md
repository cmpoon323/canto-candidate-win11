# Google 粵語候選字服務：容錯配對實測

測試日期：2026-08-15（GMT+8）。所有測試均以 `itc=yue-hant-t-i0-und` 向 Google Input Tools 候選字服務發出 HTTPS 請求，並取回最多十個候選字。

| 輸入 | 第一候選 | 服務回傳的讀音標註 | 觀察 |
|---|---|---|---|
| `neihou` | 你好 | `nei hou` | 正常近似拼音。 |
| `neihow` | 你好 | `nei hou` | 尾音多打一個 `w`，仍然首選「你好」。 |
| `leihou` | 你好 | `nei hou` | `l`／`n` 聲母混淆，仍然首選「你好」。 |
| `nihou` | 你好 | `nei hou` | 漏掉 `e`，仍然首選「你好」。 |
| `neiho` | 你好 | `nei hou` | 少打一個尾音字母，仍然首選「你好」。 |
| `neihouu` | 你可於 | `nei ho yu` | 多打一個尾音字母時，「你好」仍在第二位，排序可能改變。 |
| `neihu` | 你哭 | `nei huk` | 改變主要元音會轉向另一個合理讀音，不保證仍選「你好」。 |

實測顯示候選服務已內建部分模糊配對，特別是常見的漏字母、重複字母、近似聲母及常見粵拼差異。服務亦同時回傳每個候選字的 `annotation` 讀音標註，因此更新版將在偵測到首選讀音與用戶輸入不同時，在候選列上顯示「容錯配對」提示，例如：`leihou → nei hou`。

這並不代表可任意錯拼；誤差太大時，服務可能將另一個同樣合理的讀音排到首位。因此工具保留多個候選字，讓用戶可按數字選取，而不會自動提交候選。
